# IT Support Portal: Bugs Found

**Date:** 30 Sep 2026

**How these were found:**
- A read-only sweep of the whole codebase by three reviewers: frontend JS, the HTML/CSS ↔ JS contract, and backend/data.
- A skeptic re-checked every finding against the code, and a final "what was missed" pass followed.
- 91 raw findings were deduplicated into the entries below. A second review of the *changed* code ran after the work was done; see the last section.

**Severity:**
- **Critical**: data loss, or a feature is completely broken.
- **High**: security issue or a major feature bug.
- **Medium**: wrong results or a broken secondary feature.
- **Low**: minor, cosmetic, or rarely hit.

**Status:**
- ✅ **Fixed** in this update.
- 🟡 **Partly fixed** (see the note).
- ⬜ **Open**: documented only, with a suggested fix. Most open items also appear in [FUTURE_ENHANCEMENTS.md](FUTURE_ENHANCEMENTS.md).

Line numbers for fixed items refer to the **old** code; open items point to the **current** files.

## Found in the post-change review

After the work was done, three independent reviewers (backend, frontend JS, pages/CSS) went through the **new** code, and a skeptic re-checked each finding. They confirmed 16 issues (one was reported twice). **All 16 were fixed and re-tested.**

| ID | Sev | Issue in the new code | Fix (verified) |
|---|---|---|---|
| R-01 | Medium | Two identical installer downloads at the same moment could collide while writing the cached `.exe` (500 error). | Builds run one at a time behind a lock. The cache pruning tolerates files that disappear. *Tested: 4 simultaneous downloads → 4 valid `.exe`.* |
| R-02 | Medium | Two tickets created at the same moment could get the same server-generated ID (a false "ID already exists"). | The write lock (`BEGIN IMMEDIATE`) is taken before the next ID is chosen. *Tested: 10 simultaneous creates → 10 unique IDs.* |
| R-03 | Low | A corrupt old root `tickets.db`, or a project path containing `#`/`%`, could stop the server from starting. | The import is wrapped in error handling, and the path is opened as a proper file URI. *Tested with both.* |
| R-04 | Low | Running an installer again overwrote the Company/Site/Department/Device type an admin had set with blanks. | A blank value from an installer keeps the existing value. *Tested.* |
| R-05 | Low | The Python and Linux agents gave the same Linux PC different machine IDs, and the Python ID could change on PCs without a network card. | The Python agent now reads `/etc/machine-id` like the `.sh`, with a stable fallback. |
| R-06 | Low | The Python agent exited with code 0 even when registration failed (bad for scripted rollout). | Exits 1 on failure. *Tested.* |
| R-07 | Low | The suggested portal URL assumed port 8000 when the server ran on the default port or behind a proxy. | Uses the real scheme and port. |
| R-08 | Low | Compiler error output could fail to decode on non-English paths, hiding the real error. | `csc /utf8output` + UTF-8 decoding. |
| R-09 | Low | The `.exe` forced TLS 1.2 even for `http://` portals, which fails on PCs with only .NET 4.0. | Only for `https://` portals, and never fatal. |
| R-10 | Medium | The Ticket Details tab didn't refresh when another tab changed the ticket, and its Save sent every field, so it could **undo** a status change made elsewhere. | The details tab refreshes (fields, notes, summary) while keeping your unsaved edits, and Save sends **only the fields you changed**. *Tested with two tabs.* |
| R-11 | Low | An open quick-view popup kept stale notes and status after another tab changed the ticket. | The popup's notes and fields refresh; a status you changed but haven't saved is kept. |
| R-12 | Low | Unsaved text in a note being edited was lost when the list redrew (adding a note, switching tabs, etc.). | The draft is kept across redraws; switching to edit another note asks before discarding. *Tested.* |
| R-13 | Low | Changing a note's type while a filtered tab was open made the note "disappear". | After saving, the list follows the note to its new tab (same as adding). *Tested.* |
| R-14 | Medium | A new CSS breakpoint overrode the older ones, so the Tickets stat cards showed 3 per row on phones. | Breakpoints re-declared in the right order. *Tested: 1 column at 375 px, 2 at 800 px.* |
| R-15 | Low | A very long ticket subject overflowed the fixed-height header on the details page. | The header grows with its content (minimum 80 px). |
| R-16 | Low | In the popup, older `.assign-form` rules stretched the note-edit type selector and changed the error text size. | More specific notes-panel rules. *Tested.* |
